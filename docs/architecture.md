# Архитектура Career Quest

## Основной подход

Career Quest использует гибридную рекомендательную систему.

Детерминированный слой отвечает за:

- проверку допустимости мероприятий;
- расчёт разрывов навыков;
- применение правил `gain` и `max_level`;
- первичное ранжирование;
- проверку фактов.

AI-слой отвечает за:

- анализ нескольких факторов;
- финальное ранжирование допустимых кандидатов;
- формирование понятного объяснения.

Если AI-сервис недоступен, приложение возвращает детерминированные рекомендации.

## Компоненты

### Frontend

Технологии:

- Next.js App Router;
- TypeScript;
- Tailwind CSS;
- shadcn/ui.

Ответственность:

- профиль сотрудника;
- карьерная траектория;
- рекомендации;
- обновление прогресса;
- импорт проверочных данных;
- HR dashboard;
- обработка loading, empty и error states.

### Backend

Технологии:

- Python 3.12;
- FastAPI;
- Pydantic;
- pandas или стандартный CSV reader.

Ответственность:

- загрузка датасета;
- валидация входных файлов;
- расчёт effective skills;
- фильтрация мероприятий;
- recommendation engine;
- обновление прогресса;
- HR-агрегации;
- интеграция с AI;
- проверка AI-ответа.

### AI layer

Провайдер: NVIDIA hosted NIM API.

AI получает только:

- профиль выбранного сотрудника;
- требования следующего грейда;
- историю участия в агрегированном виде;
- список допустимых мероприятий;
- рассчитанные признаки мероприятий.

AI не получает API-ключ во frontend.

## Поток данных

1. Backend загружает `employees.json`.
2. Backend загружает `events.json`.
3. Backend загружает `skills.json`.
4. Backend загружает `activity_history.csv`.
5. Для выбранного сотрудника рассчитываются effective skills.
6. Определяется следующий грейд или карьерная цель.
7. Рассчитываются skill gaps.
8. Фильтруются недопустимые мероприятия.
9. Рассчитывается deterministic score.
10. Лучшие кандидаты передаются AI-слою.
11. AI возвращает 1–3 рекомендации.
12. Валидатор проверяет все факты в объяснении.
13. Frontend показывает результат.

## Effective skills

Уровни в `employees.json` отражают последнюю оценку навыков.

Для расчёта текущего уровня система:

1. Берёт `employee.skills`.
2. Находит `completed` активности после `last_review_date`.
3. Применяет указанный в событии `gain`.
4. Ограничивает результат через `max_level`.

Формула:

`effective_level = min(current_level + gain, max_level)`

## Фильтрация мероприятий

Мероприятие исключается, если:

- `mandatory = true`;
- роль сотрудника отсутствует в `target_roles`;
- грейд отсутствует в `target_grades`;
- prerequisites не выполнены;
- мероприятие уже завершено;
- мероприятие не развивает навыки;
- мероприятие не влияет на целевую траекторию.

Исключение для повторного участия: `EV_036`.

## Скоринг

Предлагаемая формула:

`score = 0.40 × gap_reduction + 0.20 × critical_skill + 0.15 × career_goal + 0.15 × history_fit + 0.10 × feasibility`

### Gap reduction

Показывает, насколько активность уменьшает разрыв между текущими навыками и требованиями целевого грейда.

### Critical skill

Повышает приоритет активности, если она развивает навык из `critical_skills` целевого грейда.

### Career goal

Показывает соответствие активности указанной карьерной цели.

Если карьерная цель отсутствует, используется следующий грейд текущей роли.

### History fit

Учитывает историю похожих мероприятий:

- `completed` повышает показатель;
- `dropped` снижает показатель;
- `no_show` снижает показатель;
- `declined` снижает показатель;
- учитываются тип, формат и развиваемые навыки.

История не должна полностью блокировать полезную активность. Она влияет на приоритет и объяснение.

### Feasibility

Учитывает:

- prerequisites;
- продолжительность;
- формат;
- наличие будущей сессии;
- доступность self-paced мероприятия.

## AI pipeline

AI получает top 8 кандидатов после детерминированной фильтрации.

AI должен вернуть структурированный JSON с:

- выбранными `event_id`;
- порядком рекомендаций;
- объяснением;
- используемыми факторами.

## Проверка AI-ответа

Backend проверяет:

- `event_id` существует;
- мероприятие входило в список кандидатов;
- числа совпадают с рассчитанными значениями;
- объяснение содержит минимум три фактора;
- в объяснении нет несуществующих навыков или событий.

При ошибке используется deterministic top 3.

## Обновление прогресса

После завершения активности:

1. В историю добавляется запись `completed`.
2. Для каждого навыка применяется `gain`.
3. Уровень ограничивается `max_level`.
4. Пересчитываются skill gaps.
5. Пересчитывается прогресс к следующему грейду.
6. Формируется новый набор рекомендаций.

В MVP изменения могут храниться в памяти процесса.

## HR dashboard

Backend рассчитывает:

- частоту дефицита каждого навыка;
- число сотрудников без допустимых рекомендаций;
- статистику статусов участия;
- completion rate по мероприятиям;
- no-show и dropout rate;
- участие по типам мероприятий.

HR endpoints отделяются от employee endpoints.

## Импорт проверочных данных

Endpoint импорта принимает:

- `employees.json`;
- `activity_history.csv`.

Перед добавлением проверяются:

- структура файлов;
- обязательные поля;
- уникальность employee ID;
- ссылки history на employee ID;
- ссылки history на event ID;
- допустимые статусы;
- диапазоны уровней и процентов.

Ошибка одной строки должна возвращаться понятным сообщением.

## Безопасность и приватность

- API-ключи хранятся только в переменных окружения backend.
- Frontend не обращается к NVIDIA напрямую.
- Employee view показывает данные только выбранного сотрудника.
- HR view показывает агрегаты и служебную информацию.
- Реальные персональные данные не используются.
- Ошибки API не раскрывают секреты и внутренний stack trace.

Полноценная авторизация не входит в MVP. Для демонстрации используются отдельные employee и HR routes.

## Развёртывание

### Frontend

- Vercel CLI;
- переменная `NEXT_PUBLIC_API_URL`.

### Backend

- Railway CLI;
- Dockerfile;
- переменные `NVIDIA_API_KEY`, `NVIDIA_MODEL` и `FRONTEND_URL`.

## Отказоустойчивость

- timeout AI-запроса: не более 8 секунд;
- одна повторная попытка только при временной сетевой ошибке;
- deterministic fallback;
- frontend показывает понятное сообщение об ошибке;
- `/health` не зависит от AI-провайдера.
