# Career Quest

## Общая информация

- Хакатон: HackAlem AI
- Трек: Управление
- Владелец задачи: Halyk Bank
- Тип проекта: AI и LLM engineering, product development, full stack
- Время разработки: 5 часов

## Проблема

Сотрудники получают уведомления об обучении, аттестациях, менторстве и других карьерных событиях отдельно друг от друга. Они не понимают, как конкретная активность влияет на карьерный рост, поэтому обязательные программы часто проходят формально, а добровольные активности имеют низкую посещаемость.

## Решение

Career Quest — веб-приложение с AI-навигатором, которое:

1. Показывает текущий профиль и карьерную траекторию сотрудника.
2. Сравнивает навыки сотрудника с требованиями следующего грейда.
3. Рекомендует 1–3 подходящих активности.
4. Объясняет рекомендацию минимум тремя факторами.
5. Обновляет навыки и карьерный прогресс после выполнения активности.
6. Предоставляет HR агрегированный срез по навыкам и участию.

## Пользователи

### Сотрудник

Сотрудник со стажем 1–5 лет:

1. Открывает свой профиль.
2. Видит текущий грейд и требования следующего уровня.
3. Получает рекомендации.
4. Видит объяснение каждой рекомендации.
5. Выполняет активность.
6. Видит обновлённый прогресс.

### HR

HR-специалист видит:

- наиболее частые разрывы по навыкам;
- сотрудников без подходящего следующего шага;
- участие в активностях;
- количество completed, dropped, declined и no_show.

## Входные данные

Стартовый датасет:

- `employees.json` — 200 профилей сотрудников;
- `events.json` — 40 мероприятий;
- `skills.json` — 60 навыков и требования по ролям и грейдам;
- `activity_history.csv` — 2 743 записи истории участия.

Дата среза данных: 2026-10-01.

Уровни навыков используют шкалу от 0 до 5.

## Обязательные функции

### Профиль и карьерная траектория

Для сотрудника необходимо показать:

- роль;
- текущий грейд;
- карьерную цель;
- навыки;
- требования следующего грейда;
- критичные навыки;
- историю активностей;
- доступные следующие шаги.

### Рекомендации

Система должна предложить 1–3 релевантные активности.

Рекомендация должна учитывать минимум три фактора:

- текущий и целевой грейд;
- разрывы по навыкам;
- critical skills;
- историю участия;
- карьерную цель;
- требования и доступность мероприятия.

### Объяснение

Для каждой рекомендации необходимо показать:

- текущий уровень навыка;
- требуемый уровень;
- ожидаемый уровень после активности;
- влияние активности на карьерную траекторию;
- влияние истории участия на выбор.

### Обновление прогресса

После завершения активности система должна:

1. Применить `gain`.
2. Не превышать `max_level`.
3. Обновить навыки.
4. Пересчитать прогресс до следующего грейда.
5. Пересчитать рекомендации.

### HR view

Показать:

- наиболее частые skill gaps;
- сотрудников без рекомендаций;
- статистику участия;
- completed, dropped, declined и no_show по активностям.

### Загрузка проверочных данных

Система должна принимать дополнительные:

- `employees.json`;
- `activity_history.csv`.

Жюри будет использовать дополнительные проверочные профили в формате исходного датасета.

## Правила обработки данных

- `mandatory = true` не используется для рекомендаций.
- Завершённая активность не рекомендуется повторно.
- Исключение: регулярное мероприятие `EV_036`.
- Необходимо учитывать `target_roles` и `target_grades`.
- Необходимо проверять `prerequisites`.
- При обновлении навыка применяется `gain`.
- Итоговый уровень не должен превышать `max_level`.
- Завершённые активности после `last_review_date` ещё не включены в профиль и должны учитываться при вычислении effective skills.

## Ограничения

Запрещено:

- рекомендовать активность только по одному полю;
- выдавать минимальный навык за AI-рекомендацию;
- создавать публичные рейтинги сотрудников;
- начислять баллы за обязательные процессы;
- использовать реальные персональные данные;
- показывать данные вовлечённости другим сотрудникам.

Необходимо учитывать:

- приватность данных;
- разделение employee и HR view;
- объяснимость рекомендаций;
- добровольность участия;
- запуск проекта одной командой.

## Требования по скорости

- Отклик обычного интерфейса: до 2 секунд.
- AI-рекомендация: до 10 секунд.

## MVP

В MVP входят:

1. Просмотр профиля сотрудника.
2. Карьерная траектория до следующего грейда.
3. Multi-factor recommendation engine.
4. Три объяснимые рекомендации.
5. Завершение активности и пересчёт прогресса.
6. Импорт проверочных данных.
7. Простой HR dashboard.
8. README и воспроизводимый запуск.

## Не входит в MVP

До завершения обязательного сценария не разрабатываются:

- магазин наград;
- внутренняя валюта;
- социальная лента;
- признание от коллег;
- прогноз увольнения;
- интеграция с календарём;
- интеграция с мессенджером;
- полноценная авторизация;
- публичные рейтинги;
- сложный конструктор мероприятий.

## Definition of Done

Проект считается готовым, если:

- работает основной пользовательский сценарий;
- отображается профиль и траектория;
- выдаются 1–3 рекомендации;
- объяснение использует минимум три фактора;
- завершение активности меняет прогресс;
- дополнительные профили загружаются;
- HR dashboard отображает агрегаты;
- frontend собирается без ошибок;
- backend tests проходят;
- проект запускается по README;
